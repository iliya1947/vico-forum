# PROJECT.md

## Проект

**«Форум для вайб кодеров»** — классический веб-форум для людей, которые создают программы и сайты с помощью ChatGPT, Codex, Cursor, Claude и других AI-инструментов.

Цель проекта — сохранять технические вопросы, обсуждения и проверенные решения в структурированном и пригодном для поиска виде.

## Для кого

Основная аудитория:

- новички в программировании и вайб-кодинге;
- практикующие разработчики;
- авторы технических вопросов и ответов;
- читатели, которые ищут готовое решение проблемы.

## Продуктовые принципы

- Форум остаётся классическим форумом, а не социальной лентой.
- Основная структура: **категория → раздел → тема → сообщения**.
- Публичный контент доступен без регистрации.
- Зарегистрированный пользователь может участвовать в обсуждениях.
- Автор темы может отметить проблему как решённую и выбрать лучший ответ.
- Технический контент должен удобно поддерживать текст, Markdown и код.
- AI-функции могут расширять форум, но не должны заменять его базовую механику.

## Базовые роли

- гость;
- пользователь;
- модератор;
- администратор.

Пользовательская авторизация планируется через Google OAuth.

## Техническая основа

Принятый baseline проекта:

- модульный монолит;
- React Router v8 Framework Mode + SSR + TypeScript;
- Cloudflare Workers;
- PostgreSQL + Drizzle ORM;
- Better Auth + Google OAuth.

## Мультиязычность и переводы

1. Форум изначально проектируется как расширяемо мультиязычный. Стартовые locale — `en`, `ru`, `he`, но это не закрытый список: добавление нового языка не должно требовать изменения архитектуры роутинга, SSR или i18n.
2. Locale является частью URL (`/{locale}/...`). Приоритет определения языка: URL → `user.locale` → cookie → `Accept-Language` → `en`.
3. Направление интерфейса хранится как свойство locale и поддерживает как LTR, так и RTL; Hebrew не является специальным архитектурным исключением.
4. Интерфейс использует `i18next` + `react-i18next` + `remix-i18next` v8 с SSR middleware. `i18next` является runtime-слоем отображения готовых ресурсов, а не источником вручную поддерживаемых полных словарей для каждого языка.
5. Канонический исходный язык интерфейса — English (`en`). Разработчик поддерживает один исходный набор UI-строк; переводы остальных locale генерируются автоматически по необходимости, сохраняются и повторно используются.
6. Переводы интерфейса хранятся отдельно от исходного английского текста и должны учитывать изменение исходной строки, чтобы устаревший перевод не выдавался как актуальный. Ручной перевод может переопределять машинный; при отсутствии актуального перевода используется английский fallback.
7. Локализация интерфейса и перевод пользовательского контента — отдельные сервисы с разными правилами кэширования и жизненного цикла, но они могут использовать общий сменный низкоуровневый `TranslationProvider`.
8. Основной провайдер автоматического перевода — Cloudflare Workers AI `@cf/meta/m2m100-1.2b`; Google Cloud Translation сохраняется как резервный провайдер.
9. Пользовательский контент переводится on-demand и постоянно кэшируется в PostgreSQL. Оригинал не заменяется; перевод привязывается к конкретной ревизии исходного сообщения и целевому языку.
10. Заголовки тем переводятся отдельно. Код, inline-code, URL и технические идентификаторы не отправляются на машинный перевод.
