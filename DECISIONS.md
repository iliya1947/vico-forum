# Решения

D-01. Этот PR не merge в `main`; он используется как рабочее пространство Миры.

D-02. Работа по архитектуре инструкций перезапущена с нуля от исходной цели. Предыдущие drafts, `52/52`, executability/consistency PASS и transfer package не являются основанием для новой конструкции.

D-03. Цель — не сохранить максимальное число старых правил и не минимизировать diff. Цель — получить минимальную по лишней нагрузке систему, которая реально улучшает мышление и работу агентов.

D-04. Количество самостоятельных пунктов само по себе не является метрикой компактности. Разные требования нельзя склеивать или удалять ради меньшего числа пунктов. Сокращению подлежит вода, повторы и вводящие в заблуждение пояснения.

D-05. Для каждого правила сначала устанавливается необходимость, затем правильный слой. Уникальность старой формулировки сама по себе не является основанием для сохранения.

D-06. Действующие User Instructions являются пользовательским baseline. Новые User rules допустимы только как общие улучшения интеллектуальной работы или логики, применимые во всех чатах и проектах.

D-07. Уже существующие User rules про интеллектуальную работу и логику можно только улучшать; они не удаляются и не ослабляются в ходе этой работы.

D-08. Project/team/repository/GitHub/role/permission/workflow-specific требования не переносятся в User Instructions.

D-09. Предыдущий файл `research/USER_INSTRUCTIONS_55_SOURCE.md` остаётся историческим входным материалом, но больше не является target/source-of-truth итогового User layer.

D-10. `*.current.md` остаются неизменяемыми снимками действующих источников. Старые `*.draft.md` считаются отклонёнными и должны быть сформированы заново после нового анализа.

D-11. До отдельной команды разработчика анализ в этом PR не изменяет действующие User/Project Instructions или `main:AGENTS.md`.
