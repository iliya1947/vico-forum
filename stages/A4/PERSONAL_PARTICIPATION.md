## New finding LENA-READSTATE-01 — Low/P3 (preliminary)

Automatic read-state mutation lacks actor binding to delivered page snapshot.
1. app/routes/topic.tsx 131–169 resolves topicReadState for authenticated session; loader already returns separate actor IDs for Watch/Bookmark/Mute/Block. app/forum/views.tsx 2528–2541 uses topicReadState truthiness, last delivered post and a ref key topicId:postId; submits only intent=markTopicRead and postId. There is no actor expectation and no headerActor comparison for this effect, unlike the adjacent personal controls (2969–2977).
2. app/forum/actions.server.ts 355 and markTopicRead branch 381 onward invoke editorIdentityGuard before dispatch, but app/forum/mutations.server.ts 111–119 rejects mismatched actor only if editorActorId is present. With the actual automatic payload the guard is a no-op. runForumMutation uses session at action request, not page actor. db/forum-repository.ts 1948–1990 admits active current actor, exact topic/post, monotonic upsert. It correctly protects against arbitrary client-selected victim but cannot distinguish a stale page loaded for a prior actor.
3. Conditional concrete scenario: page snapshot delivered for A, session subsequently changed to B (e.g. another same-origin tab), then hydration/effect submits that old snapshot using B's current session. All existing server conditions can succeed and advance B's cursor for a page snapshot that was not delivered to B. No ability to choose arbitrary victim or bypass current authentication asserted. This is wrong-account automatic side effect, not cross-account read access. Browser timing not reproduced; static missing fence and server effect chain established. Exact current route test app/forum/write-actions.test.ts 633–660 confirms payload without actor invokes session-scoped writer and tests inactive/missing rejection, not stale actor binding.
4. Same effect memoizes snapshot before acknowledgement, without actor or result. If same mounted topic changes actor with unchanged delivered last post, no fresh mark is submitted; on failed mark same snapshot remains deduped. These are additional investigation leads for A8; do not count another independent defect or demand blind retry. Actual mounted account-switch and failure behavior not verified. Regression criteria: stale A payload under B session causes no B write, current B snapshot can advance own marker, delivered snapshot bound and monotonicity preserved. Use isolated synthetic accounts/browser only. 
5. Prior #315 E7 verified recipient/current-session scoping and monotonicity, but did not cover this client-snapshot actor fence; READSTATE-CACHE-01 concerns caching, not this mutation. #342 corrective block concerns Watch/Bookmarks/title controls, not this automatic effect.
