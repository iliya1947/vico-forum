## New finding LENA-MEASURE-01 — Low/P3 (preliminary)

Pending appeal discovery paginates globally before applying reviewer authority. This causes false empty states, extraneous page navigation, and an aggregate side channel about appeals beyond the reviewer's authority.
1. db/user-measure-read.ts adminPendingAppeals (approximately 151–202): current authenticated manager authority and admin.usersAccess restriction checked under authz mutex; SQL selects active pending appeals across all targets, ORDER BY created_at DESC,id DESC LIMIT 26 OFFSET page*25. The loop filters only the first 25 by assertUserMeasureAuthority (including target rank and stored issuer floor); nextPage is derived from *unfiltered* row count, not the authorized set.
2. app/routes/admin-measures.tsx loader returns this page unchanged; app/measures/views.tsx 333–348 displays measuresPendingNone for zero visible rows, and nextPage as next pending appeals. English catalog explicitly says "No pending measure appeals available." 
3. Concrete permitted state: a rank-1 manager has one actionable older appeal on an ordinary target; Owner has issued 25 newer measures whose pending appeals have floor 3. All can coexist under current schema and command paths. On page 0, SQL returns 26 rows, the first 25 are all denied by issuer floor; manager sees zero results and the empty-state text although the older actionable appeal exists. Next page can show it. With 26 inaccessible appeals and no actionable appeals, nextPage still reveals there are further global pending entries, despite no authorized rows. No denied target identities, body, exact private total or mutation authority are exposed. This is a queue product defect, not an IDOR or proof of security breach.
4. A related boundary at extreme volume: reader and route cap zero-based page at 1000, but return nextPage=1001 if unfiltered lookahead exists there, which the route rejects. Do not count separately or claim such volume exists; same paging mechanism. Current defect already manifests with 26 ordinary records; not a future scale-only issue.
5. Contract: discovery is an authority-filtered reviewer queue, code's own public interface states "Only entries currently actionable by this actor are returned"; ADMIN_PANEL AP-10 requires target hierarchy and issuer floor. Existing reader tests (tests/database/user-measure-reader.test.ts 172–209) verify four-item mixed authority and nextPage=null only when total <26; do not exercise a full page of excluded rows. New independent finding relative to #315 D6 PASS. Proposed isolated regression: arrange 25 inaccessible newer pending + one older accessible, then all inaccessible, verify authorized pagination and truthful empty state. Test not run. No implementation prescription.
