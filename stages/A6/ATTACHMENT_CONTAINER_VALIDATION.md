## LENA-ATTACH-CONTAINER-READ-BUDGET-01 — P3 — current implementation

Supported archive structural validation can require more physical R2 subrequests than the configured/default Worker budget even for a valid archive far below the per-file size ceiling. This is not a claim that deployed external activation has been verified.

- attachment-container-validation.ts:244–289 validateTarStructure reads exactly one 512-byte header per entry, skipping the padded payload by size; for a nonempty archive with standard two zero end blocks it makes N+2 readExact calls. readExact invokes source.read each time, with no block cache. An ordinary ustar archive of 11,000 distinct zero-length files with correct checksums and end blocks occupies 5,633,024 bytes before optional padding, below 50,000,000 bytes, and requires 11,002 reads. It meets existing sniff/structural predicates. A similarly valid 1,100-entry archive needs 1,102 reads. No malicious payload is necessary.
- attachment-r2.ts privateObjectSource calls bucket.get for every source.read; workers/attachment-storage.ts forwards each get to actual R2 without caching. This is synchronous post-PUT validation before private asset/ref creation. Exhaustion prevents successful validation and metadata publication; ordinary dependency errors are propagated as AttachmentStorageError and route returns unavailable when control is retained; actual runtime termination/response unverified.
