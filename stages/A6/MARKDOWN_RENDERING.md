## New finding LENA-MARKDOWN-TABLE-PIPE-01 — P3 — current

Escaped terminal pipe is treated as a structural closing separator after the lexer has correctly recognized that it is not a separator. This can silently lose a whole cell from rendering and from source after a visual structure edit.

1. app/forum/technical-markdown.ts:43–60 splitCells scans each pipe and skips those preceded by an odd number of backslashes (52); after appending the final source span, line58 unconditionally pops it when trimmed input ends in a pipe. This disregards the earlier escape decision.
2. Example source (backslash is literal): 
    | A | B |
    | --- | --- |
    | first | second | extra\|
   The final pipe is escaped; there are three authored cells. splitCells constructs the three actual spans but removes the third because the last character is a pipe. tableAt:90 accepts the resulting two-cell row as rectangular instead of protecting the loss-prone shape. An ordinary two-column row ending in an escaped literal pipe without optional closing separator similarly loses a span and is misclassified as protected.
3. app/forum/markdown.tsx ForumTable renders only parsed headers and rows; the extra cell is absent in public output/Preview despite its existence in stored source. app/forum/visual-markdown-editor.tsx:515–554 renders the same two-cell shape as editable; add row/column calls onTableDimension, app/forum/markdown-editor.tsx:537–541 calls addTableDimension and sets source. technical-markdown.ts:253–271 reconstructs the entire original table span only from those already truncated cells. Thus an ordinary explicit Add row/column action removes untouched authored text from the editor Markdown, which can subsequently be saved. Merely switching mode is not claimed to rewrite source.
4. Violates EDITOR.md sections 2 and 3.3: protect complex loss-prone table shapes, preserve untouched contents, no silent deletion. Existing technical-markdown.test.ts covers escaped pipes with an actual terminal delimiter, and rejects a surplus cell with an actual terminal delimiter, not the escaped terminal case. No duplicate in prior #315 E2 findings (safe DOM), FORUM-PUB-01 or attachment classifier. Not XSS. Regression should include ordinary trailing escaped literal without separator, surplus cell ending in escaped pipe, published/preview parity, and preservation of source through visual dimension changes. Static causal chain, no actual browser execution.
