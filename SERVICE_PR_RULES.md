# Правила работы со служебным PR

Этот файл содержит действующие правила работы данного служебного PR.

`AGENTS.md` имеет приоритет. Назначение рабочих файлов описано в `STRUCTURE.md`.

## 1. Актуальность и дублирование

Рабочие файлы отражают актуальное состояние, а не последовательность всех прежних состояний. Историю изменений уже хранит Git.

Не следует копировать большие блоки одной и той же информации в несколько файлов. Краткое повторение или ссылка допустимы, если они помогают понять текущий контекст.

`WORKFLOW.md` — источник текущего оперативного состояния; старые состояния там не накапливаются.

`HISTORY.md` хранит только значимые завершённые события и не заменяет текущее состояние.

`DECISIONS.md` хранит действующие решения, а не историю обсуждения.

## 2. Личная память

Агент поддерживает свой личный файл в актуальном состоянии и хранит там только контекст, полезный ему при продолжении работы.

Личный файл не должен превращаться в хронологический дневник, копию `WORKFLOW.md` или склад чужих результатов.

Чужие личные файлы читаются только при конкретной необходимости.

## 3. Этапы, research и scratch

Необязательные stage-файлы не создаются ради одинакового шаблона.

Принятый результат исследования должен быть отражён в соответствующем плане или решении либо связан с ним ссылкой.

Другие агенты не обязаны читать `scratch/`. Перед передачей работы всё существенное из временных материалов переносится в постоянный рабочий контекст.

## 4. Чтение служебного PR

Агент не обязан читать весь служебный PR.

Обычный вход:

```text
AGENTS.md
→ RULES.md
→ TASK.md
→ WORKFLOW.md
→ свой личный файл
→ материалы активной работы
```

`STRUCTURE.md` используется как справка по устройству рабочего пространства и читается, когда нужно уточнить назначение файлов или структуру задачи.

`COMMUNICATION.md`, `DECISIONS.md`, результаты предыдущих этапов, `research/`, `HISTORY.md` и чужие личные файлы читаются в той мере, в которой они действительно нужны текущей работе.

`WORKFLOW.md` должен позволять понять, какой дополнительный контекст необходим прямо сейчас.

## 5. Передача работы

Перед передачей агент приводит относящийся контекст в актуальное состояние.

Следующий агент должен получить достаточно информации, чтобы выполнить назначение без технического пересказа разработчиком.

Комментарии служебного PR используются только как короткий сигнал управления: кто закончил, кто следующий, что ему назначено и где находится актуальный контекст.

Подробные планы, исследования, findings и отчёты в комментарии не копируются. По возможности актуальный управляющий комментарий редактируется вместо создания нового.

## 6. После завершения работы

После завершения этапа или существенной подзадачи актуализируются только действительно затронутые рабочие файлы.

Значимый результат или событие сохраняется там, где оно понадобится дальше; устаревший оперативный и временный контекст убирается.

Главный принцип: служебный PR может хранить большой объём полезной информации, но агенту для конкретного следующего действия должен требоваться небольшой и понятный набор контекста.
