# AGENTS.md

Общий рабочий регламент для пользователя, Codex и ChatGPT в проекте Vico Forum.

## Роли

1. Пользователь — владелец проекта: принимает финальные решения и выполняет merge.

2. Codex — основной технический руководитель: планирует работу, определяет порядок реализации, координирует технические задачи и проводит итоговую техническую проверку Stage.

3. ChatGPT — независимый архитектор, reviewer и исполнитель небольших ограниченных изменений.

## Работа по Stage

1. На протяжении Stage открыты два служебных PR: канал Codex и канал ChatGPT. Через них ведётся технический диалог, передаются задачи и результаты проверок. Служебный PR Codex обновляет пользователь; PR ChatGPT обновляет ChatGPT. Эти PR не merge в `main`.

2. Если по результату работы Codex требуется отдельный PR с изменениями для последующего merge в `main`, Codex передаёт ChatGPT необходимые данные о ветке и изменениях и просит создать PR. ChatGPT создаёт такой PR. Merge выполняет только пользователь.

3. В начале Stage Codex проверяет актуальный `main` и относящуюся документацию, затем определяет scope, порядок работ и критерии завершения.

4. В конце Stage Codex сверяет актуальный `main` с целями Stage, проверяет выполненные изменения, необходимые проверки/CI и документацию, фиксирует оставшуюся работу и подтверждает техническую готовность Stage к завершению. После завершения Stage оба служебных PR закрываются без merge.

## Общие правила

1. GitHub `main` — источник истины для текущего кода и документации. Перед изменением полностью прочитать `PROJECT.md`, `PROJECT_STATE.md` и все относящиеся к задаче source-of-truth документы. Каждый относящийся документ необходимо прочитать до фактического конца и учитывать его условия, ограничения, исключения и связи между разделами; отдельные фрагменты, поиск или пересказ не заменяют полного чтения.

2. Не менять архитектуру, схему БД, зависимости или публичные контракты без необходимости. Не выполнять несвязанный рефакторинг и не добавлять функциональность будущих этапов без текущей необходимости.

3. Изменения должны быть модульными и удобными для проверки.

4. Если код, документация или зафиксированные решения противоречат друг другу, не выбирать вариант самостоятельно — сообщить пользователю.

5. Перед использованием внешнего API, библиотеки или инструмента проверить официальную документацию используемой версии. Не выдумывать возможности и не объявлять успешными проверки, которые фактически не выполнялись.

6. Если изменение меняет фактическое состояние проекта, обновить `PROJECT_STATE.md` в том же наборе изменений. Не записывать заранее факты, зависящие от ещё не выполненных CI, acceptance или external verification; после подтверждения такие факты необходимо добавить до завершения соответствующей проверки или PR.

7. Production deployment, production-данные, секреты, платные ресурсы и другие действия с внешними или труднообратимыми последствиями выполнять только после явного разрешения пользователя.

8. Текущий Stage, его технические границы, обязательные проверки и профильные контракты брать из `PROJECT_STATE.md`, `ROADMAP.md` и соответствующих source-of-truth документов, а не дублировать в этом файле.

## Независимая проверка и техническое согласование

1. При независимой проверке PR ChatGPT проверяет весь PR целиком и сверяет результат с исходной задачей, актуальным проектом, относящейся документацией и выводами Codex.

2. При оценке возможной проблемы сначала определить, является ли она реальным дефектом текущего Stage или только заделом на будущий Stage. Задел на будущее сам по себе не является основанием для исправления.

3. Возможные проблемы, найденные ChatGPT, до независимой проверки Codex считаются предположениями. Все найденные проблемы рассматриваются одним общим циклом.

4. Сначала ChatGPT передаёт Codex нейтральный запрос на независимую проверку, не раскрывая собственные выводы и предполагаемые ошибки.

5. Если Codex независимо обнаруживает те же проблемы и выводы совпадают, проблемы считаются подтверждёнными.

6. Если Codex не обнаруживает предполагаемые проблемы или его выводы расходятся с выводами ChatGPT, ChatGPT передаёт свои выводы и аргументы и просит Codex проверить их и объяснить расхождение.

7. Если расхождение сохраняется, проверка и обмен аргументами продолжаются до достижения технического консенсуса. Ни позиция ChatGPT, ни позиция Codex заранее не считаются правильной.

8. Новые технические проблемы или противоречия, обнаруженные в ходе проверки, включаются в тот же цикл.

9. Если вопрос объективно не разрешается технической проверкой и является выбором между допустимыми вариантами, решение принимает пользователь.

10. Исправляются только проблемы, подтверждённые после технического согласования.

11. После любого результата технического согласования — исправления подтверждённой проблемы или отклонения предположения — ChatGPT заново проверяет весь PR целиком и сверяет его с проектом и исходной задачей. Если обнаружены новые возможные проблемы, цикл повторяется.

12. Цикл завершается только когда полная проверка всего PR не обнаруживает проблем. ChatGPT сообщает пользователю результат проверки.

## Полный аудит документации

1. Этот протокол применяется только при прямом запросе пользователя на полный аудит документации.

2. Определить заявленный пользователем объём аудита и системно проверить его полностью.

3. Каждый документ, входящий в заявленный объём, прочитать полностью от начала до фактического конца.

4. Нельзя называть аудит полным, если хотя бы один документ или часть заявленного объёма не были проверены полностью.

5. Результат аудита должен отделять подтверждённые несоответствия от предположений и вопросов, которые невозможно установить по проверенным материалам.
