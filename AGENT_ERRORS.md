# Ошибки агентов

1. **2026-11-27 — Мира, преждевременный технический handoff.** Мира определила административный read/write scope, но не зафиксировала с владельцем обязательный пользовательский сценарий «управление форумом через обычный ChatGPT»: допустимость/недопустимость отдельной формы или plugin UI, видимость GitHub transport, способ подтверждения и требование оставаться в обычном разговорном потоке. Затем эта незакрытая продуктовая часть была ошибочно передана Лёве как свобода технической реализации, что позволило плану ввести Site/plugin form без решения владельца. Правильно: до архитектурного планирования отдельно зафиксировать user journey и UX boundaries, если они определяют смысл продукта.
2. **2026-11-27 — Лёва, скрытая посылка в F-01.** План считал, что `sendFollowUpMessage` даёт поддерживаемый запуск отдельного GitHub connector. Этот API публикует сообщение компонента. OpenAI требует самостоятельного выполнения публичного tool. При выборе сквозного пути проверять правила всех переходов, включая модельный вызов зависимостей. [F-01](research/plan-review-mira.md)


- 2026-11-28 — Мира повторно сделала преждевременный technical handoff: передала Лёве embedded-AI planning до утверждения владельцем двух product-scope proposal. Причина: предложения Миры были ошибочно приняты за готовый product contract. Предотвращение: если scope помечен proposal/рекомендацией, сначала по одному закрыть существенные product decisions с владельцем, только потом передавать техническое планирование.


- 2026-11-28 — Мира смешала User AI и Admin/Moderation AI, полученные из #300 как две отдельные product-задачи: добавила Moderator Copilot в общую концепцию и объявила его «последним вопросом» User AI. Причина: общий будущий technical foundation был ошибочно перенесён на product-scope уровень. Предотвращение: product scope каждого направления прорабатывать и принимать отдельно; общие technical dependencies объединять только после закрытия обоих product contracts.

- 2026-11-28 — Business-Мира смешала готовность product concept с готовностью технической спецификации: назвала согласованный User AI concept «примерно на 90%», хотя оставшиеся перечисленные вопросы относились к technical plan. Правильно: оценивать полноту каждого артефакта по его назначению; готовый product contract не становится неполным из-за отсутствия следующего технического слоя.

- 2026-11-28 — Business-Мира после сигнала владельца `...` не выполнила очевидный следующий шаг, а затем без проверки актуального `AGENTS.md` объявила Лёву лишним и исключила обязательного архитектора из маршрута. Правильно: когда следующий шаг уже установлен, сначала выполнить доступную координацию; прямое назначение нового реализатора не отменяет стандартную роль архитектора без отдельного решения владельца.

- 2026-11-28 — Лена, #402 B-F01, преждевременное сужение: при добавлении 0080 проверила соответствие journal/snapshot/manifest, но не сверила зависимое ожидание фактического числа миграций в `tests/database/migrations.test.ts`, несмотря на аналогичный пропуск в Stage A.
