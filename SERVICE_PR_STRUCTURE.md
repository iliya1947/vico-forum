# Структура служебного PR

Этот файл описывает устройство служебных PR проекта Vico Forum, назначение их рабочих файлов и создание нового рабочего пространства.

Служебный PR — рабочая память и координационный канал команды по одной задаче. Он не является implementation PR, продуктовой документацией или архивом переписки.

## 1. Создание служебного PR

В `main` хранятся два канонических файла:

```text
SERVICE_PR_STRUCTURE.md
SERVICE_PR_RULES.md
```

При создании нового служебного PR:

1. `SERVICE_PR_STRUCTURE.md` копируется в корень его ветки как `STRUCTURE.md`;
2. `SERVICE_PR_RULES.md` копируется как `RULES.md`;
3. создаются все обязательные рабочие файлы из структуры ниже.

`SERVICE_PR_RULES.md` является готовым шаблоном локального `RULES.md`. Если конкретной задаче нужны дополнительные локальные правила, они добавляются в предусмотренный для этого раздел `RULES.md`.

После создания служебного PR рабочими документами этой задачи являются его локальные `STRUCTURE.md` и `RULES.md`.

## 2. Базовая структура

В корне:

```text
STRUCTURE.md
RULES.md
TASK.md
WORKFLOW.md
COMMUNICATION.md
DECISIONS.md
HISTORY.md
AGENT_ERRORS.md
```

Личная память:

```text
agents/
  mira.md
  lira.md
  mark.md
  leva.md
```

Рабочая область этапов:

```text
stages/
  README.md
  <stage>/
```

Рабочие области:

```text
research/
  README.md
scratch/
  README.md
```

Все перечисленные корневые файлы, четыре личных файла, каталоги `stages/`, `research/`, `scratch/` и их `README.md` обязательны для каждого служебного PR. Дополнительные файлы допускаются, когда они действительно помогают работе.

## 3. Общие файлы

1. `STRUCTURE.md` — справка по устройству рабочего пространства и назначению его файлов.

2. `RULES.md` — действующие правила работы конкретного служебного PR.

3. `TASK.md` — цель всей задачи, её границы, крупная структура и критерий завершения.

4. `WORKFLOW.md` — текущее оперативное состояние: активный этап, назначение, исполнитель, PR/head, проверка, блокер и следующий переход.

5. `COMMUNICATION.md` — общий актуальный контекст команды: существенные факты, ограничения, зависимости, незакрытые вопросы и блокеры, которые должны знать несколько агентов.

6. `DECISIONS.md` — действующие принятые решения. Для удобства можно использовать идентификаторы `D-01`, `D-02` и т. д.

7. `HISTORY.md` — значимые завершённые события задачи: этапы, merge, существенные изменения плана, переназначения, закрытые важные findings, эскалации и переходы.

8. `AGENT_ERRORS.md` — подтверждённые ошибки агентов, из которых есть полезный урок для дальнейшей работы.

## 4. Личные файлы

`agents/<agent>.md` — персональная рабочая память конкретного агента.

Каждый личный файл создаётся сразу с заголовком и пояснением:

```text
agents/mira.md
# Рабочая память Миры
Здесь хранится персональный рабочий контекст Миры, необходимый для продолжения её работы.

agents/lira.md
# Рабочая память Лиры
Здесь хранится персональный рабочий контекст Лиры, необходимый для продолжения её работы.

agents/mark.md
# Рабочая память Марка
Здесь хранится персональный рабочий контекст Марка, необходимый для продолжения его работы.

agents/leva.md
# Рабочая память Лёвы
Здесь хранится персональный рабочий контекст Лёвы, необходимый для продолжения его работы.
```

Дальше в личном файле могут храниться собственные существенные выводы, важный технический контекст, незавершённые линии анализа, персональные следствия общих решений и ссылки на нужные рабочие материалы.

## 5. Этапы

`stages/README.md` начинается строкой: `Здесь хранятся материалы отдельных этапов задачи.`

Для самостоятельного рабочего этапа можно использовать:

```text
stages/<stage>/
  SCOPE.md
  PLAN.md
  REVIEW.md
  RESULT.md
```

1. `SCOPE.md` — границы и ожидаемый результат этапа, если их полезно отделить от плана.

2. `PLAN.md` — актуальный технический план этапа.

3. `REVIEW.md` — состояние проверки реализации: PR/head, подтверждённые findings и итоговый результат проверки.

4. `RESULT.md` — компактный итог завершённого этапа, если он нужен последующим этапам.

Для маленького этапа scope может быть частью `PLAN.md`. Для сложного этапа план можно разбить на несколько смысловых файлов.

## 6. Research и scratch

1. `research/README.md` начинается строкой: `Здесь хранятся самостоятельные технические исследования, альтернативы, эксперименты и доказательства.`

2. `scratch/README.md` начинается строкой: `Здесь хранятся временные рабочие материалы, которые ещё не относятся к постоянному общему контексту.`
