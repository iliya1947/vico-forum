# Структура служебного PR

Этот файл описывает устройство служебных PR проекта Vico Forum и назначение их рабочих файлов.

При создании нового служебного PR актуальный `SERVICE_PR_STRUCTURE.md` из `main` копируется в корень его ветки как `STRUCTURE.md`.

Для существующего служебного PR его локальный `STRUCTURE.md` служит справкой по устройству рабочего пространства.

## 1. Базовая структура

В корне:

```text
STRUCTURE.md
RULES.md
TASK.md
WORKFLOW.md
COMMUNICATION.md
DECISIONS.md
HISTORY.md
AGENT_ERRORS.md
```

Личная память:

```text
agents/
  mira.md
  lira.md
  mark.md
  leva.md
```

Отдельные этапы при необходимости:

```text
stages/
  <stage>/
```

Дополнительные рабочие области:

```text
research/
scratch/
```

Количество файлов не ограничивается. Необязательные файлы создаются только когда они действительно помогают работе.

## 2. Общие файлы

1. `TASK.md` — цель всей задачи, её границы, крупная структура и критерий завершения.

2. `WORKFLOW.md` — текущее оперативное состояние: активный этап, назначение, исполнитель, PR/head, проверка, блокер и следующий переход.

3. `COMMUNICATION.md` — общий актуальный контекст команды: существенные факты, ограничения, зависимости, договорённости, незакрытые вопросы и блокеры, которые должны знать несколько агентов.

4. `DECISIONS.md` — действующие принятые решения. Для удобства можно использовать идентификаторы `D-01`, `D-02` и т. д.

5. `HISTORY.md` — значимые завершённые события задачи: этапы, merge, существенные изменения плана, переназначения, закрытые важные findings, эскалации и переходы.

6. `AGENT_ERRORS.md` — подтверждённые ошибки агентов, из которых есть полезный урок для дальнейшей работы.

## 3. Личные файлы

`agents/<agent>.md` — персональная рабочая память конкретного агента.

Там могут храниться собственные существенные выводы, важный технический контекст, незавершённые линии анализа, персональные следствия общих решений и ссылки на нужные рабочие материалы.

## 4. Этапы

Для самостоятельного рабочего этапа можно использовать:

```text
stages/<stage>/
  SCOPE.md
  PLAN.md
  REVIEW.md
  RESULT.md
```

1. `SCOPE.md` — границы и ожидаемый результат этапа, если их полезно отделить от плана.

2. `PLAN.md` — актуальный технический план этапа.

3. `REVIEW.md` — состояние проверки реализации: PR/head, подтверждённые findings и итоговый результат проверки.

4. `RESULT.md` — компактный итог завершённого этапа, если он нужен последующим этапам.

Для маленького этапа scope может быть частью `PLAN.md`. Для сложного этапа план можно разбить на несколько смысловых файлов.

## 5. Research и scratch

1. `research/` — самостоятельные технические исследования, альтернативы, эксперименты и доказательства.

2. `scratch/` — временные рабочие материалы, которые ещё не относятся к постоянному общему контексту.
