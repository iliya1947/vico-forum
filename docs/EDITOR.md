# Editor 2.0 — продуктовый и технический контракт

Постоянный контракт общего редактора Vico Forum. Перенесён из временного
`EDITOR_SPEC.md` с сохранением принятых владельцем решений 2026-10-10–15.
Статус реализации и фактически выполненные проверки — в `PROJECT_STATE.md`;
наличие этого документа само по себе не означает acceptance или разрешение merge.
Общий pre-release Stage 6 (внешняя инфраструктура) остаётся на паузе.

## 1. Назначение и исходная основа

- Развивать существующий общий Markdown-редактор форума из PR #210, а не создавать несвязанные формы для разных сценариев.
- Использовать его при создании тем, ответах, вопросах Help & solutions и редактировании опубликованных сообщений.
- Сохранить единый контракт содержимого сообщения (Markdown/body) и совместимость с существующим безопасным рендерингом, цитированием, ответами, переводами и публикацией. Используется общий source-positioned редактор на React с точной строкой Markdown и единой историей изменений; отдельная внешняя WYSIWYG-библиотека не требуется.
- Сначала обеспечить корректную функциональность; окончательная косметическая/UX-доводка — отдельный общепроектный refinement-pass в конце проекта перед первым публичным production-релизом и не блокирует завершение текущего PR Editor 2.0.

## 2. Два режима одного редактора

### Простой

- По умолчанию при первом использовании — **Простой**, визуальный WYSIWYG: пользователь видит готовое форматирование без символов Markdown.
- Предназначен для обычных форумных сообщений.
- Сложные технические конструкции, созданные в Расширенном режиме (включая код, Diff и сложные таблицы), показываются как содержимое готового сообщения, но не редактируются напрямую в Простом. Обычный текст вокруг них редактируется свободно.
- В Простом режиме отдельные постоянные вкладки Write/Preview/Split не нужны. Кнопка «Предпросмотр» переключает между визуальным редактированием и просмотром готового сообщения (§3.5).

### Расширенный

- Редактирование исходной Markdown-разметки, включая технические сообщения и код.
- Представления **Markdown / Просмотр / Split**, выбираемые через меню единой кнопки «Предпросмотр» (§3.5). В Split исходник и результат показываются вместе, прокрутка синхронизирована; на телефонах области располагаются вертикально.
- Доступны инструменты Простого режима плюс расширенные инструменты для кода и сложных конструкций.

### Общее поведение — согласовано владельцем (пункт №1, 2026-10-10)

- **Единый источник содержимого — Markdown.** Простой WYSIWYG и Расширенный режим работают над одним сообщением, не над двумя независимыми версиями текста.
- **Переключение режима само по себе ничего не меняет.** Если пользователь не редактировал содержимое, исходный Markdown должен оставаться побайтово неизменным, включая пробелы, переносы строк и исходные технические конструкции. Никакой автоматической «нормализации» только при просмотре/переключении.
- **Обычное форматирование** (заголовки, списки, ссылки, цитаты и прочее поддерживаемое) редактируется в обоих режимах.
- **Сложные блоки** (программный код, Diff, сложные таблицы и неподдерживаемые/нестандартные конструкции) в Простом режиме сохраняются и отображаются, но не редактируются непосредственно: для изменения предусмотрен переход в Расширенный режим.
- Редактирование обычного текста **до и после сложного блока** не должно переписывать или повреждать этот блок. Неизвестная и невалидная Markdown-разметка также не должна молча удаляться или исправляться.
- **Undo/Redo сохраняет историю действий через переключение режимов**; пользователь может отменить и повторить изменение, сделанное до перехода в другой режим. По возможности сохраняются позиция курсора и выделение, с адекватной адаптацией к способу отображения.
- Если пользователь **явно изменил форматирование** в Простом режиме, соответствующий Markdown может измениться: сохраняются смысл, содержимое и нетронутые фрагменты, но побайтовая идентичность уже изменённого участка не обещается.
- Запоминать последний выбранный Простой/Расширенный режим **локально в браузере с привязкой к ID авторизованного пользователя** и восстанавливать при следующем открытии редактора; выбор общий для создания темы, ответа и Help & solutions.
- Не синхронизировать эту настройку между устройствами: каждый пользователь может независимо выбрать режим на ПК и телефоне. Не путать Простой/Расширенный режим с вкладками Markdown/Просмотр/Split внутри Расширенного.

**Критерий готовности механизма:** последовательные переключения без редактирования не изменяют источник; правка текста рядом со сложным блоком сохраняет блок; Undo/Redo продолжает работать после перехода между режимами. Конкретная техническая реализация будет выбрана на этапе разработки.

## 3. Форматирование и панели инструментов

### Компоновка desktop — уточнения владельца 2026-10-10

- **Единая верхняя строка:** справа рядом друг с другом находятся **одна кнопка переключения «Простой / Расширенный»**, кнопка **«Предпросмотр»** и кнопка **«Полный экран»**. Это не отдельный ряд и не двухкнопочный переключатель.
- **Переключатель режима — согласован владельцем:** одна текстовая кнопка в правой части верхней панели **показывает режим, в который переключит**, а не текущий. Когда редактор в **Простом**, на кнопке написано **«Расширенный»**; после нажатия редактор переходит в Расширенный, и подпись меняется на **«Простой»**. Следующее нажатие возвращает Простой режим и подпись «Расширенный». Вместо одной непонятной иконки используется видимый текст (дополнительная иконка необязательна). Смена режима не изменяет содержимое сообщения (см. раздел 2).
- **На той же строке, слева от трёх управляющих кнопок, находится панель инструментов форматирования — в полном составе первого согласуемого макета:** **Undo**, **Redo**, визуальный разделитель, **B (жирный)**, **I (курсив)**, **S (зачёркнутый)**, **ссылка**, **маркированный список**, **нумерованный список**, **цитата**, **emoji**, **меню «•••»**. Порядок именно такой; Undo/Redo — рядом с зеркальными иконками. Второстепенные функции остаются в компактном меню; на desktop это единая строка вместе с кнопками режима, предпросмотра и полного экрана справа.
- **Без вертикального переноса отдельных инструментов:** B/I/S и остальные кнопки имеют собственные неделимые места на панели; нельзя допускать, чтобы из-за нехватки ширины они складывались в столбец. При уменьшении ширины второстепенные инструменты лучше убирать в меню «•••» либо использовать адаптивную компактную компоновку.
- **Единая нижняя строка:** слева — вложения; справа — «Отмена» и «Опубликовать» (для опубликованной правки — «Сохранить»). Индикатора сохранения черновика нет.
- Порядок основных элементов desktop-панели, переключение представлений (§3.5) и состав меню дополнительных инструментов (§3.6) согласованы. Точные размеры, отступы и детали адаптивной компоновки определить при реализации.
- На узких экранах элементы допускается адаптивно сгруппировать без потери доступности; desktop-требование об общей строке сохраняется для ширины, где оно помещается.

### Переключение представлений — согласовано владельцем (пункт №3.5, 2026-10-11)

- **Одна кнопка «Предпросмотр» в правой части верхней строки** остаётся на том же месте рядом с кнопками «Простой / Расширенный» и «Полный экран». Не добавлять дополнительные строки, вкладки или постоянные кнопки для выбора представления.
- **Простой режим:** кнопка переключает визуальное редактирование и просмотр готового сообщения целиком.
- **Расширенный режим:** эта же кнопка открывает компактное меню из трёх вариантов: **Markdown** (только исходник для редактирования), **Просмотр** (только готовое сообщение без редактирования) и **Split** (исходник и готовый результат одновременно).
- Выбранное представление визуально отмечается в меню. Для Split действуют уже согласованные правила расположения и синхронизации прокрутки; смена представления не изменяет исходный Markdown и не создаёт независимых версий сообщения.

### Меню дополнительных инструментов «•••» — согласовано владельцем (пункт №3.6, 2026-10-11)

- **Простой режим:** в меню «•••» доступны заголовки H2/H3, спойлер, горизонтальный разделитель, очистка форматирования и вставка без форматирования.
- **Расширенный режим:** тот же набор плюс «Вставить как код», вставка блока кода, таблицы, поиск и замена.
- Разделять команды меню на понятные группы по назначению.
- **Мобильные и узкие экраны:** при недостаточной ширине дополнительные кнопки основной панели переходят в это же меню, оставаясь доступными; не выстраивать инструменты вертикально отдельным рядом.
- Кнопки переключения режима, предпросмотра и полноэкранного редактора остаются доступны вне «•••», без добавления ещё одной строки управления.
- Отдельная кнопка/инструмент для Diff не требуется: это обычный блок кода с языком `diff`, отображаемый по правилам §3.2.

### Инструменты Простого режима

- Отмена и повтор действий (Undo/Redo). **Иконка повтора — точное зеркальное отражение иконки отмены**; располагаются рядом, с подсказками.
- Жирный, курсив, зачёркнутый текст.
- Ссылки, цитаты.
- Маркированный и нумерованный списки.
- Emoji.
- Заголовки (в частности H2/H3).
- Очистка форматирования. Команда применяется только к выделенному содержимому; если выделение пустое, применяется ко всему содержимому редактора. Снимается поддерживаемое inline-оформление текста и ссылки; структурные/технические блоки не превращаются в plain text.
- Спойлер.
- Создание обычной Markdown-таблицы с визуальным редактированием ячеек/строк/столбцов.
- Горизонтальный разделитель.
- Вставка без форматирования.
- Панель не перегружать: основные функции на виду, второстепенные — в дополнительном меню.

### Инструменты Расширенного режима

- Всё из Простого режима.
- Встроенный (inline) код и многострочные блоки кода с подсветкой синтаксиса.
- Указание языка программирования для блока; не ограничиваться только популярными языками.
- Tab/Shift+Tab и отступы нескольких строк.
- Ручное Markdown-редактирование структуры и содержимого таблиц, включая сложные случаи, которые Простой режим не может представить без потерь.
- Split, полный экран.
- Переключаемая нумерация строк в блоках кода.
- «Умная вставка кода» с сохранением отступов и переносов.
- Diff-представление с различением добавленных и удалённых строк.
- Необязательное имя файла над блоком кода (например, app/routes/home.tsx).
- Поиск и замена внутри длинного сообщения.
- Автоматические парные скобки и продолжение отступов **только при редактировании кода**, не для обычного Markdown.
- Инструменты для кода логически сгруппировать; не рассыпать по всей панели.
- Рендеринг кода должен сохранять понятные технические идентификаторы, в том числе в RTL; код отображается LTR.

### Блоки программного кода — согласовано владельцем (пункт №3.1, 2026-10-10)

- **Язык:** можно указать вручную; если он не указан, блок отображается без языковой подсветки синтаксиса. Не ограничивать произвольно перечень возможных языков.
- **Имя файла:** необязательная отдельная подпись над блоком кода, не часть скопированного содержимого.
- **Копирование:** кнопка копирует только исходный текст кода, без имени файла, служебной панели и номеров строк.
- **Длинные строки:** по умолчанию не переносятся; доступно ручное включение переноса. Без переноса сохраняется горизонтальная прокрутка блока. Выбор запоминается локально для текущего аккаунта (§9.1).
- **Номера строк:** выключены по умолчанию, включаются отдельной кнопкой, но не меняют исходный код. Выбор запоминается локально для текущего аккаунта (§9.1).
- **Редактирование:** содержимое блока изменяется только в Расширенном режиме. Простой режим показывает готовый блок; действие «Редактировать код» переключает в Расширенный и переводит к соответствующему блоку.
- **Безопасность:** код никогда не запускается форумом, доступен только для безопасного отображения и копирования.
- Изменение вспомогательных настроек просмотра (номера строк, перенос) не должно изменять Markdown сообщения.

### Diff — согласовано владельцем (пункт №3.2, 2026-10-10)

- **Только простая подсветка стандартных Markdown-блоков кода с языком `diff`**: добавленные строки (начинающиеся с `+`) выделяются зелёным, удалённые (с `-`) — красным, остальное остаётся нейтральным; символы знаков изменения сохраняются и различимы без цвета.
- Не нужен отдельный Diff-редактор, генератор сравнения, автоматическое вычисление изменений, построчные действия, side-by-side и иные специальные инструменты Diff. Используется обычный механизм отображения блоков кода; стандартные действия блока (например, копирование) сохраняются.
- Копирование выдаёт исходный Diff-текст без потерь и цветового оформления, включая знаки `+`/`-`, контекстные строки и заголовки. Редактирование выполняется в Расширенном режиме на общих правилах блоков кода.
- Подсветка влияет только на отображение, не преобразует и не нормализует исходный Markdown.

### Таблицы — согласовано владельцем (пункт №3.3, 2026-10-10)

- **Обычные Markdown-таблицы** отображаются как таблицы в готовом сообщении и в Простом WYSIWYG-редакторе. В Расширенном режиме пользователь редактирует Markdown и видит результат в предпросмотре.
- **Простой режим:** можно создать новую обычную Markdown-таблицу визуальной командой; непосредственно редактируются её ячейки, а строки и столбцы можно добавлять через встроенное меню без ручного ввода Markdown.
- **Расширенный режим:** редактирование структуры и содержимого обычных таблиц через Markdown без обязательного визуального табличного конструктора.
- **Вставка из Excel и Google Sheets:** в Простом режиме корректно преобразуем скопированные табличные данные в таблицу, сохраняя строки, столбцы и текст ячеек. Если преобразование не может быть выполнено без потери данных, нужен безопасный вариант с явным предупреждением; правила вставки исходного Markdown в Расширенном режиме не меняются.
- **Широкие таблицы** имеют горизонтальную прокрутку и не обрезают содержимое.
- **Сложные/нестандартные таблицы**, которые простой Markdown-таблицей без потерь не представить, в Простом режиме доступны только для просмотра, а редактируются в Расширенном.
- **Не добавляем** табличные вычисления/формулы, фильтрацию, сортировку или объединение ячеек.
- **Сохранность источника:** просмотр и переключение между режимами не должны повреждать таблицу или исходную Markdown-разметку; действуют общие round-trip правила из раздела 2.

### Спойлеры — согласовано владельцем (пункт №3.4, 2026-10-10)

- **По умолчанию спойлер свёрнут**; читатель раскрывает и сворачивает его нажатием на заголовок/кнопку.
- Заголовок необязателен. Если автор его не указал, показывать локализованную подпись «Спойлер».
- Содержимое может включать обычный текст, ссылки, списки, изображения и блоки кода, как и остальные поддерживаемые части сообщения.
- **Простой режим:** спойлер — визуальный блок, обычное содержимое редактируется непосредственно; технические блоки внутри доступны только для просмотра, редактировать их можно в Расширенном режиме.
- **Расширенный режим:** спойлер редактируется через Markdown-совместимую разметку; точную безопасную форму хранения/рендеринга определить при реализации.
- Раскрытие/сворачивание — исключительно состояние отображения, не изменяет Markdown или исходное содержимое.
- **Не средство разграничения доступа:** спойлер только визуально скрывает текст, не использует паролей и не создаёт приватного контента.

## 4. Предпросмотр, цитаты, ответы

- Предпросмотр должен соответствовать опубликованному виду сообщения и использовать согласованную безопасную семантику рендеринга.
- Поддержать «Цитировать сообщение целиком» и «Цитировать выделенное».
- Цитата содержит видимого автора и постоянную ссылку/якорь на исходное сообщение (например, #15).
- В Простом цитата — визуально редактируемый блок; в Расширенном — Markdown-представление. При переключении не терять автора, ссылку и содержимое.
- В **опубликованном сообщении**, при чтении цитаты:
  - Если цитата занимает **от одной до пяти видимых строк**, показать полностью.
  - Если занимает **шесть и более видимых строк**, показать **первые три видимые строки** с кнопкой «Показать всю цитату».
  - После раскрытия показать цитату целиком и кнопку «Свернуть».
  - Учитывать реальные видимые строки с переносами и шириной устройства, а не только символы перевода строки.
  - Автор и ссылка на оригинал всегда видимы.
  - Сворачивание — исключительно представление при чтении; оригинальная цитата полностью сохранена.
- Существующий механизм Reply/Quote и постоянных ссылок на сообщения сохраняется; не смешивать прямой ответ с упоминанием пользователя.

## 5. Состояние открытого редактора

По решению владельца от 2026-10-20 пользовательские черновики и автосохранение
не входят в текущий Editor 2.0. Текст и Undo/Redo живут только в памяти открытой
формы. Переключение режима, Preview/Fullscreen и ошибка валидации не теряют этот
buffer. Reload/navigation не восстанавливают неопубликованный текст; повторное
открытие правки загружает опубликованную revision.

Нет local/server text cache, 60-second autosave, межвкладочного/межустройственного
восстановления, выбора версий черновика, «Моих черновиков» и draft discovery.
Настройки интерфейса редактора (§9) сохраняются отдельно от содержимого сообщения.

### Возможные будущие функции

Drafts and autosave остаётся в `Under development` как возможная будущая функция.
Её persistence, recovery, cross-device sync, conflict semantics и срок хранения
будут проектироваться отдельно; прежние требования о 60 секундах и 30 днях не
являются контрактом текущего редактора или временных uploads.

## 6. Вложения и изображения

- Поддержать вставку изображения из буфера (Ctrl+V), перетаскивание Drag & Drop, выбор файла через кнопку «Прикрепить», вставку изображения в тело сообщения.
- Изображения показываются в тексте с возможностью открыть оригинал; другие файлы — компактным вложением с названием, размером и скачиванием.
- Перед публикацией вложение можно удалить или заменить.
- Явные состояния загрузки и ошибки; текст при проблеме загрузки не теряется. Состояние незавершённых вложений хранится в открытой upload operation без текста.
- Широкая поддержка технических форматов, не короткий закрытый список: изображения PNG/JPG/WebP/GIF; файлы исходного кода (JS/TS/JSX/TSX/Python/PHP/C++/C# и др.); TXT/MD/LOG/JSON/YAML/XML/ENV и конфигурации; CSV/SQL; ZIP/7Z/TAR/GZ; PDF и распространённые документы.
- Не принимать исполняемые опасные файлы (например, EXE) как обычные вложения; архив сам по себе не означает безопасное содержимое.
- Для текстовых технических файлов, где поддерживается формат, предусмотреть безопасный просмотр.
- При загрузке потенциально секретосодержащих файлов (например, .env) показывать предупреждение о паролях/токенах.
- **Первичное хранилище и лимит** утверждены владельцем (пункт №4.3): Cloudflare R2 Standard, максимум **50 МБ на один файл**. Лимит сделать изменяемым через конфигурацию без архитектурной переделки; реальные ограничения и стоимость сервиса повторно проверить перед подключением.
- Не вводить произвольные per-user квоты на число файлов или суммарный объём на этом этапе.
- Неиспользуемые файлы обрабатывает ограниченный повторяемый процессор `ForumAttachmentCleanup` с durable delete claims и проверкой действующих ссылок. Реальное фоновое расписание и внешнее R2-подключение остаются отложенным Stage 6; локально используются адаптер и эмулятор.

### Загрузка вложений — согласовано владельцем (пункт №4.1, 2026-10-10)

- При выборе/вставке/перетаскивании файла **сразу начинать его загрузку**, не откладывая её до нажатия «Опубликовать».
- Пока файл загружается, пользователь может продолжать редактировать текст сообщения.
- Для каждого файла показывать состояние загрузки (включая прогресс, когда доступен) либо ошибку.
- При неуспешной загрузке доступны действия **«Повторить»** и **«Удалить»**; ошибка загрузки не удаляет набранный текст.
- **Публикация доступна только после успешной загрузки всех оставленных вложений.** Незавершённые и ошибочные загрузки блокируют публикацию, но не работу в редакторе.
- Неиспользуемые временные файлы освобождаются при закрытии operation и bounded cleanup; опубликованные ссылки защищают shared assets.

### Доступ и удаление вложений — согласовано владельцем (пункт №4.2, 2026-10-10)

- **До публикации:** временный файл upload operation доступен только автору. Предварительная загрузка не делает файл публичным и не предоставляет доступ по одной только известной ссылке.
- **После публикации:** файл становится доступен тем, кто имеет право читать соответствующее сообщение; в публичной части форума это обычно все посетители, без входа.
- **При редактировании опубликованного сообщения:** новые прикреплённые файлы остаются непубличными до успешного сохранения обновлённого сообщения; открытая форма редактирования не меняет доступ к уже опубликованным вложениям.
- **При удалении вложения из сообщения:** доступ к нему через это сообщение и его ссылку должен прекращаться, если файл больше не используется другой опубликованной публикацией или действующей upload operation. Не удалять общие файлы, на которые ещё есть действующие ссылки/привязки.
- **При удалении сообщения:** вложения перестают выдаваться на основании удалённого сообщения; сохраняются только те файлы, которые продолжают использоваться в других доступных сообщениях или действующих upload operations.
- **Физическая очистка хранилища:** осиротевшие файлы удаляет автоматический фоновый механизм без ручных действий администратора. Удаление ссылки и прекращение выдачи файла — немедленное действие в логике форума; физическое удаление данных из хранилища может произойти позже, после проверки отсутствия других действующих связей.
- Точные сроки очистки, способ хранения и проверки доступа, работа с кешем и защита от гонок сохранения/удаления определяются при реализации. Специальных настроек доступа к отдельному вложению для пользователей не предусматривается.

### Хранилище и размер — согласовано владельцем (пункт №4.3, 2026-10-10)

- **Основное файловое хранилище — Cloudflare R2 Standard**; сам форум работает на Cloudflare Workers.
- **Максимальный размер одного вложения — 50 МБ.** Конкретный лимит должен задаваться конфигурацией, чтобы в дальнейшем его можно было пересмотреть без смены архитектуры.
- **PostgreSQL/Neon хранит сведения о файлах и связи с сообщениями и временными upload operations, а не двоичное содержимое вложений.**
- Не вводить пользовательские квоты на общее число или суммарный объём файлов только ради этого решения (см. выше). Ограничение 50 МБ относится к одному файлу.
- **Отложено:** в дальнейшем исследовать подключение *дополнительного бесплатного хранилища* для снижения затрат при росте использования. Пока не выбирать провайдера, не обещать бессрочную бесплатность и не внедрять мультихранилище заранее. При возвращении к вопросу оценить фактическую доступность бесплатного уровня, ограничения, стабильность, стоимость запросов/выдачи и трудоёмкость переноса.
- Подключение R2, создание бакета, платные действия и фактические значения стоимости — отдельный этап реализации, не совершаются при согласовании спецификации.

### Безопасность файлов и готовность к антивирусу — согласовано владельцем (пункт №4.4, 2026-10-10)

- Сохранять широкую поддержку технических исходников, документов, изображений и архивов в рамках допустимых типов; явно опасные исполняемые форматы (.exe, .msi, .dll, .scr и аналогичные) отклонять. Сервер не выполняет пользовательский код, не распаковывает архивы и не запускает содержимое файлов.
- **Проверка типа на сервере:** сверить расширение, заявленный MIME и фактические признаки содержимого. Для узнаваемых бинарных форматов проверять характерные сигнатуры/структуру файла и обнаруживать очевидные несовпадения или запрещённые исполняемые заголовки даже под обманным именем. Для текстовых файлов (например, .js/.py/.txt) нет надёжной универсальной бинарной сигнатуры: применять соответствующие правила обработки, не заявляя о полной идентификации или доказанной безопасности.
- Заявленным клиентом имени, расширению и MIME не доверять как единственным доказательствам формата. Проверки не обещают обнаружения всех вредоносных, полиглотных, зашифрованных или вложенных в архив объектов и не заменяют антивирус.
- **Проверка перед доступом:** сначала предварительная приватная загрузка в R2; до подтверждения допустимого размера/типа и завершения обязательных проверок файл недоступен публично и не разрешён к использованию в опубликованном сообщении. Фактический тип и размер берутся из серверных данных, а не клиентских утверждений.
- Для безопасного просмотра и выдачи использовать контролируемые форматы/типы ответа; активный HTML/SVG, скрипты и другие потенциально исполняемые форматы не рендерить и не исполнять в контексте происхождения (origin) форума. Разрешённые технические исходники — как текст/скачивание, не как исполняемый контент.
- Архивы разрешены к загрузке, но сами по себе не подтверждают безопасность вложенных файлов; система не должна представлять их как проверенные на вирусы.
- Для конфигураций с возможными секретами (например, .env) показывать предупреждение о токенах/паролях с возможностью отказаться от загрузки либо продолжить.
- При отклонении файла показывать понятную причину, не теряя текст редактора и другие корректные вложения.
- **Готовность к антивирусной интеграции:** предусмотреть одну изолированную проверочную границу/интерфейс и модель статусов, способную различать проверку типа, ожидание/результат дополнительного сканирования и отказ. Пока сканер не подключён, не запускать имитацию антивируса, не показывать файл как «проверен антивирусом», не добавлять обязательные внешние сервисы и платные зависимости.
- В будущем сканер (например, ClamAV или сервис-провайдер) подключается в этот единый этап без переделки существующей загрузки, доступа и публикации; если он включён как обязательная проверка, файл остаётся недоступен для публикации до положительного результата, а ошибка/неопределённый результат не считается успехом. Конкретный провайдер, обработчик фонового сканирования и интерфейс интеграции определяются при реализации соответствующей возможности.
- Это продуктовые требования к механизму, а не требование заранее строить отдельную подсистему антивируса.

### Системные сигналы о подозрительных вложениях — согласовано владельцем (дополнение к пункту №4.4, 2026-10-10)

- **При любом обнаруженном признаке подозрительного вложения** — несовпадении расширения, MIME и содержимого; попытке маскировки или подмены типа; обнаружении запрещённого исполняемого формата; подозрении на вредоносный код/вирус (в том числе по результату будущего антивируса); других аномалиях проверки файла — **автоматически фиксировать системный сигнал безопасности для администраторов и модераторов**.
- **Сигнал должен попадать строго в «Требуют внимания» → режим «Безопасность» → первую группу «Вложения» (`mode=security&group=attachments`).** Это системный сигнал от механизма проверки вложений, а не пользовательская жалоба и не обычный сигнал пользователя о качестве Help-вопроса; не направлять такие сигналы в режим «Сигналы» или «Жалобы». Проверять права и использовать действующий центр модерации. Решение владельца 2026-10-11.
- Передавать модератору пригодные для разбора сведения: причину/результат проверки, заявленный и распознанный тип, имя и идентификатор файла, время события, идентификатор загрузившего пользователя и доступный контекст upload operation/сообщения. Не публиковать содержимое подозрительного файла и не открывать его автоматически при просмотре сигнала. Если файл удалён, сохранять достаточные метаданные события для рассмотрения.
- **Подозрительный/отклонённый файл не публиковать и не выдавать посетителям.** Не путать подозрение с установленным вирусом: в сигнале показывать фактический результат и основание, а не недоказанный диагноз.
- Повторные технические события по одной загрузке не должны создавать бессмысленные дубликаты модераторских задач; сигнал должен быть надёжно зафиксирован и не теряться при отклонении/очистке файла.
- **Порядок интеграции:** PR #217 расширенного режима «Требуют внимания» merged в `main` 2026-10-11. В PR #215 группа «Вложения» выделяется под реальные события безопасности; существующие «Сигналы» обслуживают Help-сигналы, а «Жалобы» остаются независимыми. При реализации загрузки файлов добавить долговечную фиксацию системных событий и их выборку/обработку через группу «Вложения» с серверными правами. Не создавать параллельную админ-очередь и не показывать фиктивные события.
- Группа «Вложения» читает реальные durable события проверки файлов. Она остаётся read-only: вымышленные события и ещё не согласованные действия модерации не добавляются.

## 7. Упоминания и уведомления

- При вводе @ + части имени показывать подсказки подходящих пользователей; выбор связывает видимую ссылку на профиль с устойчивым идентификатором аккаунта, а не только изменяемым именем.
- В одном сообщении можно упомянуть нескольких участников; работает в обоих режимах.
- Уведомление об упоминании отправляется **только после успешной публикации сообщения или сохранения его опубликованной правки**, не при наборе текста.
- Повторные упоминания одного человека в одном сообщении не создают дублей.
- Упоминания в цитатах и блоках кода не отправляют уведомления.
- Если участнику уже назначено уведомление об ответе, упоминание в том же сообщении **не создаёт отдельного дублирующего уведомления**.
- Ответ на сообщение и упоминание пользователя остаются различными механизмами.

### Упоминания при редактировании опубликованного сообщения — согласовано владельцем (пункт №7.1, 2026-10-10)

- Если после сохранения правки опубликованного сообщения появился **новый упомянутый пользователь**, отправить ему уведомление.
- За **уже упомянутого в этом сообщении** пользователя повторно не уведомлять при последующих правках.
- Удаление упоминания из текста **не отзывает** ранее отправленное уведомление.
- Если ранее упомянутый пользователь был удалён из текста, а затем повторно добавлен в то же сообщение, **новое уведомление ему не отправлять**. Для этого учитывать уже уведомлённых по конкретному сообщению, а не только текущие упоминания в тексте.
- Остальные правила раздела 7 сохраняются: не уведомлять при черновых правках, не учитывать цитаты и код, не создавать дубли при совпадении с уведомлением об ответе.

## 8. Публикация, ошибки и редактирование

### Публикация

- Публикация без отдельного окна подтверждения.
- Кнопка «Опубликовать» **неактивна**, только если **нет ни содержательного текста, ни хотя бы одного успешно загруженного вложения**, либо если хотя бы одно оставленное вложение ещё загружается или его загрузка завершилась ошибкой. Пробелы/пустые строки не считаются содержательным текстом. При ошибке загрузки пользователь может повторить попытку или удалить проблемное вложение.
- Когда всё готово, кнопка становится активной автоматически; рядом понятно объяснять причину блокировки.
- Во время публикации временно блокировать повторную отправку.
- Ctrl+Enter публикует сообщение при готовности к отправке.
- При сбое сервера/интернета текст и вложения остаются на месте. Повторный запрос не должен создавать дубликат, даже если первый был обработан, но ответ потерялся.
- Очищать текущую форму после подтверждённой публикации; сервер независимо проверяет запрос, права и idempotent operation identity.
### Публикация без текста — согласовано владельцем (пункт №8.1, 2026-10-10)

- **Сообщение с хотя бы одним успешно загруженным вложением можно опубликовать без текста.** Например, ответ скриншотом или архивом. Подписи к файлам и изображениям необязательны.
- Если нет содержательного текста и готовых вложений, публикация недоступна. Если любое оставленное вложение ещё загружается или загрузилось с ошибкой, публикация недоступна до завершения загрузки, повторной попытки или удаления проблемного файла.
- Применять одинаково к разрешённым сценариям публикации; конкретный способ хранения ссылки на файл определяется реализацией и не должен превращать пустое сообщение в ошибку.

### Редактирование опубликованных сообщений

- Использовать те же Простой/Расширенный режимы и инструменты.
- Изменения живут в открытой форме; опубликованная версия меняется **только по явной кнопке «Сохранить»**.
- «Отмена» закрывает форму без изменения опубликованного сообщения; повторное открытие начинает новую operation из опубликованной revision.
- Сохранять предыдущие опубликованные версии (историю изменений), даты и авторов редактирования.
- **Историю изменений разрешает effective permission `forum.post.history.read`.** Moderator/admin получают его по умолчанию; изменяемые role grants, custom roles и per-user allow/deny overrides действуют по `docs/auth/AUTHORIZATION.md`. Серверная проверка прав обязательна, простого скрытия UI недостаточно.
- Пользователь без effective `forum.post.history.read` не может смотреть историю изменений, даже собственного сообщения. Название роли само по себе доступ не разрешает и не запрещает.
- Всем видна только отметка «Отредактировано» и дата последнего редактирования.
- Не расширять этот блок до создания админ-панели или новой системы жалоб/сигналов.

## 9. Языки, направление, орфография

- **Любые языки и письменности**, Unicode/диакритика/emoji, без ограничения списком локалей интерфейса (EN/RU/HE — не перечень разрешённых языков сообщений).
- Автоматическое определение направления **каждого абзаца** по его содержимому (LTR/RTL) с ручным переключателем направления.
- Смешанный текст (языки, технические термины, команды, пути) не должен ломаться; код всегда LTR даже на RTL-странице.
- Направление и исходные символы должны сохраняться при смене режимов/предпросмотра.

- **Реализованный способ явного выбора (2026-10-15):** в «•••» доступны Авто / LTR / RTL для выбранного текстового абзаца, заголовка или элемента списка. Принудительный выбор сохраняется в исходнике как видимый в Расширенном режиме завершающий атрибут `{:vico-dir=ltr}` либо `{:vico-dir=rtl}`; «Авто» удаляет атрибут. Собственный Markdown-рендерер распознаёт только два точных разрешённых значения, не выводит атрибут в публикации и визуальном режиме, а исходную строку сохраняет для текущего editor buffer, истории и редактирования опубликованного текста. Экранированный или неподдерживаемый атрибут остаётся буквальным текстом. Это **явное форматирование сообщения**, а не локальная настройка интерфейса из §9.1. Обычный режим просмотра и смена режимов не должны самопроизвольно создавать или удалять этот атрибут.

### Проверка орфографии: принято поэтапное решение

- **Сейчас:** штатная браузерная проверка орфографии, без зависимости от конкретного браузера.
- По умолчанию в Простом режиме включена; в Расширенном выключена, но может включаться пользователем. Настройка включения/отключения запоминается **локально по ID аккаунта** (§9.1).
- Не выполнять автоматическую замену слов: исправления предлагает браузер, пользователь выбирает самостоятельно.
- В кодовых блоках по возможности выключать проверку. Для Markdown source в едином текстовом поле браузер может не уметь исключить отдельные фрагменты кода: не обещать невозможное.
- Качество/доступность словарей зависит от браузера/ОС; это не ограничивает язык создаваемого сообщения.
- Предусмотреть границу между редактором и механизмом проверки, чтобы позже **заменить браузерную на собственную систему со словарями**, не переписывая весь редактор; не создавать сейчас движок или универсальную плагинную платформу.

### Локальные настройки редактора — согласовано владельцем (пункт №9.1, 2026-10-10)

- **Настройки хранятся в браузере и привязываются к устойчивому ID авторизованного пользователя**, а не к общему браузеру/устройству. При переключении аккаунтов не подхватывать предпочтения другого пользователя.
- Запоминать для каждого аккаунта на данном устройстве последний выбор **Простой / Расширенный**, **включение проверки орфографии**, **перенос длинных строк кода** и **номера строк кода**. Согласованные значения по умолчанию действуют, если настройки для аккаунта ещё не сохранены.
- Настройки на **ПК и телефоне независимы**: автоматически между устройствами не синхронизируются, дополнительных серверных запросов ради них не делать.
- При выходе из аккаунта настройки не стираются; при повторном входе в тот же аккаунт возвращаются. При смене аккаунта интерфейс редактора применяет только настройки нового пользователя. Настройки удаляются отдельно от содержимого сообщений; draft-cache UI в текущем редакторе отсутствует.
- Эти настройки влияют только на работу и отображение редактора; не должны изменять исходный Markdown, содержание сообщения. Технический способ локального хранения выбрать при реализации.

## 10. Вставка содержимого из других приложений

- В Простом режиме обычный Ctrl+V пытается сохранять поддерживаемую структуру: заголовки, списки, ссылки, цитаты, жирное/курсив, код.
- При вставке из IDE/GitHub сохранять точные отступы и переводы строк программного кода.
- Копирование таблицы из Excel/Google Sheets — вставка как таблицы, если возможно корректное преобразование.
- Картинка из буфера становится вложением.
- Ctrl+Shift+V — только текст без форматирования.
- Отдельная команда «Вставить как код».
- В Расширенном режиме исходный Markdown вставляется без изменения разметки.
- Не переносить из HTML чужие шрифты, цвета, размеры, исполняемые скрипты и небезопасную разметку.
- Если сложное форматирование невозможно корректно преобразовать, предложить безопасный вариант вместо незаметной потери данных.

## 11. Клавиатура и мобильные устройства

### Горячие клавиши

- Ctrl+Z — отмена; Ctrl+Y **или** Ctrl+Shift+Z — повтор отменённого.
- Ctrl+B — жирный; Ctrl+I — курсив; Ctrl+K — ссылка.
- Ctrl+Enter — опубликовать; Enter сам по себе не публикует.
- Tab/Shift+Tab управляют отступами только при редактировании кода в Расширенном; в Простом Tab участвует в навигации по интерфейсу.
- Ctrl+F — поиск внутри Расширенного редактора, только когда это не ломает обычный поиск браузера вне редактора.
- На macOS — соответствующие Cmd-комбинации.
- Горячие клавиши ограничены контекстом редактора и не должны перехватываться глобально на форуме; у кнопок подсказки сочетаний.
- Текст отправляется только через явные Publish/Save; фонового автосохранения нет.

### Адаптивность

- На телефоне по умолчанию компактный встроенный редактор; часто используемые инструменты на панели, остальные в меню.
- Кнопка полноэкранного редактора; доступны оба режима и весь инструментарий.
- В Расширенном — удобный доступ к Tab/Shift+Tab/отступам, вертикальный Split, горизонтальная прокрутка длинных строк кода без насильственного переноса.
- Панель доступна во время набора, экранная клавиатура не закрывает курсор; размер редактора можно менять.
- Поддержать клавиатурную доступность, фокус, подписи для ассистивных технологий, мобильную навигацию, разные направления текста и основные браузеры.
- Для desktop приняты базовые две единые строки управления (см. раздел 3); финальная детализация компактной компоновки ещё не согласована.


## Границы реализации и проверки

- Общий Markdown source, Undo/Redo и Simple/Advanced остаются в `markdown-editor`,
  `editor-document` и `visual-markdown-editor`; Preview/public rendering — `ForumMarkdown`.
  Programmatic paste согласуется с focused DOM; native input/IME и whitespace-only
  editable range сохраняют surface/focus. Table paste и cross-leaf Enter сохраняются.
- `useEditorAttachments` держит pending/selected состояние в памяти. Каждая открытая
  форма/account/context получает отдельный opaque operation ID. Reload не восстанавливает
  текст или старый набор uploads. Published edit начинает с текущих public refs.
- Upload немедленно сохраняет проверенные bytes и private temporary ref; server
  owner/context/permission/origin checks действуют независимо от client identity.
  Stable file ID позволяет повторить ambiguous upload без второго logical asset.
  Failed/pending uploads блокируют штатную публикацию, не мешая набору текста.
  Remove снимает файл только из mounted selection/UI, в том числе после ambiguous
  transport failure. Temporary server ref остаётся в private pool до Publish/Save,
  Cancel или idle cleanup; per-file DELETE больше не поддерживается. Поздний ACK
  не возвращает снятый файл в selection. Не выбранный pool никогда не публикуется.
- Final submit передаёт exact selected uploaded IDs и retained published IDs. Repository
  под scope/post locks проверяет owner/context/operation, verification, live refs и
  cleanup state; atomically пишет публикацию и её refs, закрывает operation и сохраняет
  fingerprint receipt. Лишние temporary refs не публикуются. Text snapshot/CAS не нужен.
- Post edit сохраняет `expectedRevisionId` и revision history. Remove/Cancel не меняют
  public refs; Save атомарно применяет retained/new selection. Concurrent stale Save
  отклоняется без частичной публикации/удаления файлов. При явном rebase берётся
  актуальный published attachment baseline, из него вычитаются только явные локальные
  Remove; новые локальные uploads сохраняются отдельно. Лишь затем продвигается
  expectedRevisionId. Отсутствие файла в старой форме не считается Remove; repeated
  rebase сохраняет этот intent, а новая concurrent revision вновь отклоняет stale Save.
- Cancel/Publish terminally закрывают operation; late upload/retry не возрождает её.
  Temporary refs abandoned operation освобождаются процессором после 24 часов без
  успешного нового upload. Удержание pool refs сохраняет дату последнего такого upload
  даже после локального Remove всех файлов. Remove/read/failure и idempotent retry ACK
  уже существующего asset не продлевают idle. Объект может быть удалён только после existing one-hour grace от создания, с
  durable delete claim/lease и trigger locks; published/shared refs защищены всегда.
  Реальное расписание cleanup и внешняя инфраструктура — отложенный Stage 6.
- Existing merged schema с историческими `draft_id` именами используется только для
  temporary refs, completion markers и publication receipts. Text draft repository,
  endpoints и recovery runtime отсутствуют; legacy text rows не читаются/не импортируются.
  Migrations 0034–0044 не переписываются; draft snapshot migration 0045 в пакет не входит.
- Private R2 выдаётся через controlled download с актуальной ref проверкой. Raster inline,
  source preview как инертный текст, остальные файлы скачиваются. Размер и тип проверяются
  streaming boundary; FixedLengthStream сохраняется для Workers R2. Антивирус не имитируется.
- Native submit replay выполняется в следующей event-loop task, сохраняя validation и
  submitter. Loading и pending upload блокируют повторную отправку во всех четырёх flows.
- Applicable regressions используют components, настоящий PostgreSQL и Chromium с
  Worker/local private R2. Проверять отсутствие text storage/requests после >60s, reload,
  in-memory history, attachment-only/subset/text-only publish, retry/lost ACK, Cancel,
  terminal/cleanup races, post revision conflict, downloads и F7 whitespace/focus/IME.
  Старый CI не заменяет проверки нового exact head. Отдельная owner visual acceptance
  и Pages preview выполняются только по прямому запросу владельца.
- Production migration/deployment, external R2/Neon, scheduling и AV provider не входят
  в этот PR. Финальная косметическая доводка остаётся общепроектным refinement-pass.
