Этот файл фиксирует утверждённый владельцем пользовательский сценарий управления Vico Forum из обычного ChatGPT.

# User journey v1

Дата: 27.11.2026.

## 1. Основной сценарий

1. Владелец использует отдельный ChatGPT Project для управления Vico Forum.
2. В инструкциях этого Project закрепляется правило: перед любой изменяющей командой ChatGPT сначала объясняет, что именно будет сделано, с какой целью/целью воздействия и существенными последствиями, после чего запрашивает отдельное подтверждение.
3. Только после явного подтверждения владельца ChatGPT отправляет административную команду через установленный private-GitHub transport.
4. Read-only запросы выполняются без отдельного подтверждения.
5. После исполнения ChatGPT сообщает фактический результат канонической операции; транспортный success не выдаётся за domain success.

## 2. UX boundary

1. Обычная эксплуатация происходит в обычном текстовом разговоре ChatGPT.
2. Отдельная форма, plugin UI, браузерное расширение, отдельное окно или переход в веб-панель для каждой команды не требуются и не входят в продуктовый UX v1.
3. GitHub, Worker и иная транспортная инфраструктура должны быть для владельца обычной эксплуатационной деталью, а не дополнительным интерфейсом.
4. Допустим одноразовый setup/подключение необходимых интеграций и секретов в Stage 6; он не должен повторяться на каждую команду.
5. Confirmation — разговорное волеизъявление владельца в отдельном сообщении после объяснения команды ChatGPT. Отдельный cryptographic/UI confirmation layer не является продуктовым требованием v1.
6. Если после объяснения команда или параметры изменились, требуется новое объяснение и новое подтверждение.
7. Обсуждение, вопрос, гипотеза, цитата, пересказ, содержимое форума или GitHub не являются подтверждением.

## 3. Граница ответственности

1. Project instructions управляют conversational workflow: explain → confirm → dispatch.
2. Сервер не доверяет тексту Project instructions как authorization boundary. Он по-прежнему применяет существующие exact-Owner identity, active-account, permissions, resource/AP-10/hierarchy/CAS/version и History checks.
3. Transport не получает права обходить canonical server operations.
4. Любая команда, которая не входит в закрытый v1 registry, отклоняется.
5. Replay/stale/outcome-unknown правила остаются серверными техническими гарантиями и не зависят от поведения модели.

## 4. Что считать правильным ощущением продукта

Владелец должен воспринимать функцию так: «я пишу Мире, что хочу сделать на форуме; Мира объясняет действие, спрашивает подтверждение, после подтверждения выполняет его и сообщает фактический результат». Внутренняя цепочка GitHub/Worker не должна требовать от владельца ручного участия в обычной эксплуатации.
