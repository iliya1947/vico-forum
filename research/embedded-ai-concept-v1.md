Этот файл фиксирует концепцию встроенного AI Vico Forum до утверждения полного product scope и до технического планирования.

# Embedded AI — product concept v2

Дата: 28.11.2026.
Статус: частично утверждён владельцем; незакрытые product decisions отмечаются отдельно.

## 1. Главная роль пользовательского AI

По прямому решению владельца центральная функция пользовательского AI — **консультант-навигатор по самому Vico Forum**, а не универсальный технический консультант.

Его цель: помочь пользователю быстро понять:
1. куда идти;
2. где искать нужную информацию;
3. какая существующая тема/раздел/страница подходит;
4. где правильно задать вопрос;
5. каким форумным механизмом воспользоваться.

Формула продукта: **«Спроси Vico, где и что искать/делать на форуме»**.

## 2. Vico Consultant как навигатор

Пользователь может написать обычным языком, например:
1. «Где спросить про ошибку Cloudflare Worker?»
2. «Найди тему про Better Auth и Google OAuth».
3. «Куда писать, если перевод сообщения неправильный?»
4. «Где посмотреть свои закладки?»
5. «Как пожаловаться на сообщение?»
6. «Где изменить язык?»
7. «Есть уже тема про такую ошибку?»
8. «Какой раздел подходит для моего вопроса?»

Консультант должен отвечать не абстрактной инструкцией, а **конкретной навигацией по Vico**:
1. подходящая существующая тема;
2. несколько наиболее релевантных тем;
3. нужный раздел/category;
4. canonical forum page или feature;
5. правильный следующий forum action.

## 3. Главный пользовательский цикл

### Шаг A — пользователь формулирует намерение

Пользователь описывает, что хочет найти или сделать на форуме.

Это может быть:
1. найти решение;
2. найти похожую тему;
3. понять, куда задать вопрос;
4. найти функцию форума;
5. понять, как работает конкретный механизм Vico;
6. перейти к нужной пользовательской/служебной странице.

### Шаг B — консультант определяет тип намерения

Консультант классифицирует запрос как минимум в одну из групп:
1. knowledge/topic discovery;
2. section/category routing;
3. Help & solutions routing;
4. feature/navigation help;
5. settings/account/help surface;
6. moderation/reporting/help route;
7. question-placement assistance.

Это внутренняя логика; пользователь не обязан выбирать режим вручную.

### Шаг C — консультант использует данные самого форума

Для topic discovery используются:
1. lexical + semantic relevance;
2. title/body/tags;
3. solved state;
4. best answer;
5. current visibility/current revisions;
6. category/section context.

Для navigation help используются:
1. canonical route/feature registry Vico;
2. permission-aware доступность;
3. текущий locale;
4. известный контекст пользователя/страницы только в разрешённых границах.

### Шаг D — консультант приводит пользователя в правильное место

Результат должен быть actionable:
1. «Вот тема, которая больше всего похожа»;
2. «Тебе нужен раздел X»;
3. «Это делается здесь»;
4. «Для такого вопроса лучше Help & solutions»;
5. «Такой темы не нашёл — вот куда создать новую».

Консультант не должен превращать простой navigation request в длинную AI-консультацию.

## 4. Поиск правильной темы — ключевая функция

Semantic/hybrid retrieval остаётся важным foundation, но теперь его роль определена точнее: он нужен прежде всего, чтобы **найти правильную существующую тему/решение и не заставлять пользователя вручную разбираться в структуре форума**.

Особенно важно:
1. понимать естественные формулировки, не совпадающие с title;
2. находить релевантные темы на другом языке;
3. повышать полезность solved/best-answer тем;
4. не скрывать релевантные unsolved discussions;
5. не показывать hidden/private content.

Обычный Search продолжает существовать и при AI outage работает lexical-only.

## 5. Помощь с выбором места для нового вопроса

Если подходящей темы нет, консультант помогает определить:
1. category;
2. section;
3. нужен ли обычный topic или Help & solutions;
4. наиболее подходящие tags;
5. при необходимости — коротко сформулировать title.

Это не универсальный AI-editor и не генерация полноценного технического ответа.

## 6. Объяснение возможностей форума

Консультант должен хорошо знать продукт Vico и уметь отвечать на вопросы вида:
1. где мои Watch/Bookmarks/Mute/Block;
2. как отметить best answer;
3. где пожаловаться;
4. где поменять настройки;
5. как посмотреть профиль/уведомления;
6. какие возможности доступны текущему пользователю.

Источник таких ответов — актуальный product/navigation contract Vico, а не произвольные общие знания модели.

Если функция недоступна текущему пользователю, консультант не должен выдавать её как доступную.

## 7. Что не является основной ролью

В первом релизе консультант **не должен позиционироваться как универсальный программист/технический эксперт**.

Он может кратко объяснить содержимое найденной темы или помочь понять, что в ней обсуждается, но:
1. его главная задача — ориентировать в Vico;
2. он не должен конкурировать с форумными участниками полноценными generated solutions;
3. general technical Q&A не является обязательным scope;
4. внешний web-search не нужен для основной концепции.

## 8. Summary и объяснение темы

Допустима контекстная функция:
1. «О чём эта тема?»
2. «К чему здесь пришли?»
3. «Какой ответ выбран лучшим?»

Она помогает ориентироваться в найденной теме, а не создаёт самостоятельный summary-product.

Summary строится on-demand по текущему разрешённому содержимому и не становится canonical content.

## 9. Editor integration

AI-помощь в Editor нужна только в той мере, в какой она продолжает навигационный сценарий:
1. если подходящей темы нет — помочь выбрать раздел/tags;
2. предложить более понятный title;
3. указать, что пользователь, возможно, задаёт вопрос не в том месте.

Полноценное переписывание body/генерация технического решения не является обязательной частью концепции.

## 10. Moderator Copilot

AI для модерации остаётся отдельной permission-scoped поверхностью:
1. advisory harmful-content signals;
2. duplicate/spam candidates;
3. complaint brief;
4. evidence/checklist assistant.

Он не разделяет protected context с User Consultant и не получает domain-write authority.

## 11. Связь с Owner ChatGPT control

В Vico остаются три разные AI-роли:
1. **User Consultant** — навигация, discovery и помощь найти правильное место/тему.
2. **Moderator Copilot** — помощь в разборе moderation/Complaints.
3. **Owner ChatGPT control** — административное управление форумом владельцем.

Их нельзя объединять в одного универсального агента из-за разных identity, data boundaries и authority.

## 12. Graceful degradation

1. AI недоступен → обычная навигация и Search работают.
2. Semantic retrieval недоступен → Search работает lexical-only.
3. Consultant недоступен → все canonical routes/features остаются доступны напрямую.
4. Moderator AI недоступен → Attention/Complaints работают без изменений.
5. Paid fallback запрещён.

## 13. Product priority

### Core user AI

1. Forum/navigation consultant.
2. Semantic/hybrid topic discovery.
3. Correct section/category/Help routing.
4. Forum feature/how-to guidance.
5. Contextual topic explanation/summary.

### Supporting functions

1. Similar topics before creating a new topic.
2. Suggested section/tags/title when no existing topic fits.
3. Permission-aware navigation hints.

### Not core for v1

1. General-purpose technical consultant.
2. External web research.
3. Autonomous answers/posts.
4. Full AI rewriting of user content.
5. Persistent personal AI memory.

## 14. Remaining product decisions

После этого решения владельца ещё нужно последовательно определить:
1. **РЕШЕНО:** Consultant доступен только авторизованным пользователям.
2. Должен ли Consultant помнить conversation state между страницами/сессиями.
3. Насколько глубоко он должен понимать permission-aware navigation для Admin/Moderator surfaces.
4. Нужна ли отдельная постоянная точка входа «AI Consultant» или достаточно общей точки + контекстных входов.
5. Как показывать несколько найденных тем: один лучший ответ или короткий ranked set.
6. Нужен ли on-demand topic summary в обязательном v1.
7. Какой минимум Moderator Copilot обязателен в первом релизе.


## 15. Решение владельца — доступ к Consultant

Consultant доступен **только авторизованным пользователям**.

Следствия для product scope:
1. Guest не получает диалоговый Consultant.
2. Public Search и обычная публичная навигация форума остаются доступны без авторизации.
3. Consultant может надёжно опираться на authenticated user identity, locale и доступные пользователю forum capabilities.
4. Guest-rate-limit и анонимная AI abuse-модель для Consultant в v1 не требуются.
