# Структурные объединения USER_INSTRUCTIONS.draft.md

Источник: `USER_INSTRUCTIONS.draft.md` после удаления только подтверждённо избыточных old 17 / 29 / 44.

Цель этого этапа: проверить, какие из 52 самостоятельных смыслов можно хранить в одном пункте **без удаления guard'ов и без превращения нескольких независимых операций в длинный составной пункт**.

## Критерий безопасного объединения

Объединение считается безопасным только если одновременно выполняются условия:

1. правила срабатывают в одной и той же точке reasoning/action;
2. их удобно выполнить как одну последовательную проверку;
3. после объединения обе исходные защиты остаются явно сформулированы;
4. объединение не требует скрытой посылки, чтобы восстановить исходный смысл;
5. правило не становится «контейнером» для нескольких независимых операций только ради уменьшения числа пунктов.

## Подтверждённые безопасные объединения

### A. current 2 + current 49 — discipline ответа

Исходно:
- 2: отвечать по существу, без воды;
- 49: не добавлять ненужные инструкции, действия и следующие шаги.

**Решение: SAFE-MERGE.**

Обе проверки относятся к формированию пользовательского ответа: первая убирает нерелевантный текст, вторая — нерелевантные user-facing действия. Они различаются по смыслу, но выполняются в одной точке и могут остаться двумя явными предложениями внутри одного пункта.

Важно: это объединение структурное, не семантическое удаление.

### B. current 4 + current 5 — verification fallback

Исходно:
- 4: изменяемую техническую информацию проверять по актуальным первичным источникам и версии;
- 5: если существенное проверить нельзя — явно сказать «Информация не проверена».

**Решение: SAFE-MERGE.**

Это одна операция:
1. попытаться проверить;
2. если существенная проверка невозможна — обозначить предел знания.

Обе части остаются явными.

### C. current 9 + current 10 — confidence calibration

Исходно:
- 9: категорический вывод только при достаточных основаниях; иначе сохранить неопределённость;
- 10: не повышать уверенность без нового основания и переносить неопределённость в зависимые выводы.

**Решение: SAFE-MERGE.**

Это одна последовательная операция калибровки:
1. определить допустимую степень уверенности исходного вывода;
2. сохранить её в зависимых выводах, пока не появилось новое основание.

### D. current 18 + current 19 — state applicability

Исходно:
- 18: факт/правило/решение применять только к подходящим сущности, версии, состоянию, времени и области;
- 19: не смешивать несовместимые версии/состояния/времена/объекты как одно состояние.

**Решение: SAFE-MERGE.**

Обе части относятся к одной операции построения фактического состояния:
1. проверить применимость каждого основания;
2. не складывать применимые по отдельности, но несовместимые между собой основания в одно состояние.

current 20 не включать: он регулирует уже другую операцию — invalidation выводов после изменения состояния.

### E. current 21 + current 22 — inherited-context trust

Исходно:
- 21: не переносить ошибку предыдущего ответа ChatGPT как факт/условие/основание;
- 22: не принимать вывод/план/трактовку другого агента как факт без проверки существенных оснований.

**Решение: SAFE-MERGE.**

Обе части задают одно правило доверия к уже находящемуся в контексте AI-output: наличие текста в истории само по себе не делает его установленным основанием.

Два источника риска должны остаться названы отдельно внутри объединённого пункта:
- собственный предыдущий ответ;
- вывод другого агента.

### G. current 28 + current 29 — decision authority

**Решение: SAFE-MERGE.**

Это одна authority check:
1. не выводить полномочие из фактической способности/участия;

current 30 не включать: scope уже выданного разрешения/исключения — отдельная операция.

### H. current 36 + current 37 + current 38 — ask-or-act threshold

Исходно:
- 36: неопределённость сама по себе не блокирует продолжение;
- 37: при несущественно различающихся допустимых вариантах без закреплённого owner выбрать разумный вариант самому;
- 38: спрашивать пользователя при существенной неустранимой неопределённости или принадлежащем ему существенном выборе.

**Решение: SAFE-MERGE.**

Это единое decision tree:
1. harmless uncertainty → продолжать;
2. несущественный свободный выбор → выбрать самому;
3. существенная неопределённость или owner-choice → спросить пользователя.

current 35 не включать: он определяет необходимость предварительной самостоятельной проверки до вопроса.
current 39 не включать: он определяет stop condition анализа, а не owner/choice routing.

### I. current 43 + current 44 — classification integrity

Исходно:
- 43: проверить валидность категорий и не принуждать объект к неподходящей классификации;
- 44: не выводить свойства объекта только из присвоенной категории.

**Решение: SAFE-MERGE.**

Это одна операция работы с категорией:
1. проверить, допустима ли сама классификация;
2. не приписывать объекту дополнительные свойства только из ярлыка.
