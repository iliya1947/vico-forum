# User journey gap review — 27.11.2026

## Проверено

Сверены `TASK.md`, `DECISIONS.md`, `research/user-journey-v1.md` и `research/product-scope-v1.md` после последовательного согласования пунктов 1–12 с владельцем.

Устаревшее решение D-09 (routine mutation без отдельного подтверждения) исправлено как противоречащее принятому правилу «любой write → explain → confirm → dispatch».

## Остались продуктовые развилки

1. **Массовые операции — РЕШЕНО.** Один подтверждённый фиксированный набор может выполняться последовательностью существующих canonical единичных mutations; новые targets после подтверждения не добавляются, итог per-target.
2. **Составная команда — РЕШЕНО.** Единицей подтверждения является пользовательская задача, а не число внутренних mutations. «Перенести тему, закрыть и закрепить» — одно действие владельца и одно подтверждение; внутренняя декомпозиция остаётся технической деталью.
3. **Контекст confirmation — РЕШЕНО.** Подтверждение относится к конкретному последнему объяснённому pending action в текущем разговорном контексте. Межчатового confirmation state нет; отдельный продуктовый таймер не требуется.
4. **Фоновый мониторинг — РЕШЕНО.** V1 строго request-driven. Будущий scheduler/event trigger должен быть добавляем без переписывания canonical read/analysis mechanism, но сам background monitoring сейчас не реализуется.

После решения пунктов 1–4 найден ещё один существенный вопрос:

5. **Частичный сбой — РЕШЕНО.** Обычная составная задача останавливается на первом существенном сбое без автоматического отката уже committed шагов. Массовая задача продолжает остальные независимые targets и возвращает per-target итог; внутри каждого target составная последовательность всё равно stop-on-first-failure.


После решения пункта 5 незакрытых продуктовых развилок, способных изменить UX или архитектурную политику v1, по текущим материалам не осталось.
