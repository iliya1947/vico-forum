# User journey gap review — 27.11.2026

## Проверено

Сверены `TASK.md`, `DECISIONS.md`, `research/user-journey-v1.md` и `research/product-scope-v1.md` после последовательного согласования пунктов 1–12 с владельцем.

Устаревшее решение D-09 (routine mutation без отдельного подтверждения) исправлено как противоречащее принятому правилу «любой write → explain → confirm → dispatch».

## Остались продуктовые развилки

1. **Массовые операции — РЕШЕНО.** Один подтверждённый фиксированный набор может выполняться последовательностью существующих canonical единичных mutations; новые targets после подтверждения не добавляются, итог per-target.
2. **Составная команда — РЕШЕНО.** Единицей подтверждения является пользовательская задача, а не число внутренних mutations. «Перенести тему, закрыть и закрепить» — одно действие владельца и одно подтверждение; внутренняя декомпозиция остаётся технической деталью.
3. **Жизнь conversational confirmation.** Не определено, действует ли подтверждение только как непосредственный ответ на последний pending action в том же чате либо может сохраняться после промежуточного разговора/в другом чате Project.
4. **Фоновый/регулярный мониторинг.** Не определено, входит ли в v1 возможность просить Миру следить за форумом/жалобами регулярно между разговорами, или v1 строго request-driven: анализ и управление только когда владелец обращается в чат.

Других продуктовых развилок, способных изменить UX или техническую архитектуру v1, по текущим материалам не найдено.
