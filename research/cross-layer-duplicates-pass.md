# Межслойные дубли — current-based drafts

Scope: `USER_INSTRUCTIONS.draft.md` ↔ `PROJECT_INSTRUCTIONS.draft.md` ↔ `AGENTS.draft.md`.

Цель этого прохода — найти межслойные повторы. Ничего не удаляется автоматически: дубли разделены на delete-safe, частичные и обязательные из-за разной аудитории.

## 1. Подтверждённые delete-safe дубли / повторные данные

### D1 — Project: отдельное требование «исходи из цели»

Project:
> Всегда исходи из цели: не делай выводов и не действуй, пока не понимаешь, зачем это нужно.

AGENTS:
- `Логика 1`: установить текущую цель и смысл задачи;
- `Логика 5`: самостоятельное действие должно приближать текущую цель.

Для ChatGPT в проекте Project rule 2 уже требует полностью читать актуальный `main:AGENTS.md`. Поэтому Project-фраза не добавляет отдельного поведения.

Классификация: **DELETE-SAFE из Project**.

### D2 — Project: «проверь очевидное / не принимай первую трактовку»

Project:
> Перед ответом проверь, не упущено ли очевидное из текущей задачи. Не принимай первую трактовку автоматически; сопоставь её с контекстом.

AGENTS:
- `Логика 1`: цель и смысл по контексту + не принимать первую правдоподобную трактовку автоматически;
- `Принципы 3`: замечать очевидные проблемы, зависимости и противоречия вокруг текущей работы.

В проекте ChatGPT обязан читать AGENTS, поэтому отдельная Project-копия поведения не нужна.

Классификация: **DELETE-SAFE из Project**.

### D3 — Project: таблица имён и моделей

Project повторяет:
- Лира — ChatGPT-6;
- Мира/Ари — ChatGPT-5.6 Sol;
- Марк — Codex-6 Sol;
- Лёва — Codex-6.1 Sol.

То же соответствие уже содержится в `AGENTS.md → Роли`.

Но Project дополнительно требует **использовать** эти имена при идентификации/обращении/упоминании. Это требование не удаляется.

Классификация: **DATA-DUPLICATE**. Таблицу Project можно заменить ссылкой на `AGENTS.md → Роли`, сохранив правило использования имён.

### D4 — Project rule 2: пояснение назначения AGENTS

Project rule 2:
> ...полностью прочитай актуальный `AGENTS.md`; он задаёт рабочий регламент.

Сам `AGENTS.md` уже объявляет себя рабочим регламентом. Обязательство получить `main` и полностью прочитать файл уникально и сохраняется; хвост `он задаёт рабочий регламент` — пояснительный дубль.

Классификация: **PARTIAL DELETE-SAFE** — удалить только поясняющий хвост.

## 2. Сильные перекрытия, но пока НЕ delete-safe

### O1 — Project rule 3 ↔ AGENTS Review 5 + General 3

Project:

- future groundwork сам по себе не основание для исправления.

AGENTS:
- `Проверка PR 5`: findings делятся на current-task, external current-Stage и future work; future work сам по себе не основание менять реализацию;
- `Общие правила 3`: не выполнять работу будущих Stage без текущей необходимости.

Перекрытие сильное, но Project trigger — **любая проблема, найденная ChatGPT в работе Codex**, а AGENTS Review 5 формально расположен в PR-review scope. Удаление Project rule 3 сейчас могло бы сузить область.

Классификация: **STRONG OVERLAP, KEEP пока не доказана эквивалентность области**.
