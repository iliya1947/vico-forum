## Stress matrix

### S1 — первая правдоподобная трактовка
Ошибка: агент принимает первое разумное толкование, хотя другое materially меняет действие.

Guard: rule 16; цель отдельно закреплена rule 15.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Rule 16 локально задаёт один decision: если трактовка материальна, сравнить очевидные варианты с контекстом.

### S2 — прямое поручение подменяется «правильным процессом»
Ошибка: конкретное поручение заменяется типовым процессом или более общей целью.

Guard: rule 21.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Rule 21 остаётся единым precedence contract: совместимые прежние условия сохраняются, прямое поручение задаёт текущее действие.

### S3 — техническая возможность превращается в permission
Ошибка: агент технически может выполнить внешнее действие и считает этого достаточным.

Guard: rule 18.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Rule 18 теперь является одним admissibility gate для самостоятельного действия: действие должно быть обосновано, вести к цели, находиться в scope, быть разрешено и не наносить существенного вреда цели. Authority и exception semantics вынесены в rules 19–20.

### S4 — исполнитель присваивает решение владельца
Ошибка: агент знает достаточно/может выполнить действие и поэтому принимает принадлежащее другому решение.

Guard: rule 19.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Authority выделена отдельно от permission/action gate: знание/работа/проверка/техвозможность не создают полномочия; установленный владелец решения не подменяется.

### S5 — лишняя перепроверка подтверждённого факта
Ошибка: неизменившийся подтверждённый факт проверяется повторно «на всякий случай».

Guard: rule 22.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Revalidation triggers перечислены явно. Соседняя часть про диагностическую гипотезу остаётся в том же rule, но обе ветки относятся к одному diagnostic uncertainty contract и не конкурируют при данном решении.

### S6 — доступная диагностика перекладывается на пользователя
Ошибка: агент просит пользователя проверить то, что способен установить сам.

Guards: rules 23 и 32.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Rule 23 даёт прямой ask-gate; rule 32 отдельно требует выполнить доступные проверки/диагностику до действия пользователю. Stop/choice logic больше не находится в том же пункте.

### S7 — runaway analysis
Ошибка: проверки продолжаются ради абсолютной уверенности, хотя остаточная неопределённость не меняет результат.

Guard: rule 26.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Stop condition выделен в самостоятельный rule.

### S8 — корреляция превращается в причину
Ошибка: совпадение/временная последовательность трактуется как причинность.

Guard: rule 9.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Causality guard явный; соседний modality guard короткий и не создаёт конкурирующего decision path.

### S9 — преждевременное «готово»
Ошибка: одна успешная проверка или часть критериев выдаётся за завершённость всей задачи.

Guard: rule 11.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

### S10 — старый факт переносится на новый exact state
Ошибка: изменился объект/version/state/head, но старый вывод считается действующим.

Вердикт: **SEMANTIC PASS / EXEC PASS**.

Rule 13 локально требует пересмотреть только зависимые выводы/решения/проверки после материального изменения.

### S11 — согласие агентов считается независимым подтверждением
Ошибка: несколько агентов повторяют вывод на одном основании, и confidence повышается как будто evidence независим.

Вердикт: **SEMANTIC PASS / EXEC PASS**.
