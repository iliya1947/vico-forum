# Задача

Рабочий PR Миры для полного перепроектирования слоёв инструкций ChatGPT в проекте Vico Forum.

## Исходная цель

Получить минимальную, понятную и исполнимую систему инструкций, которая реально улучшает качество мышления и работы агентов и уменьшает количество тупых решений.

Работа начинается заново от требуемого поведения, а не от сохранения предыдущих drafts, guard-count, PASS-метрик или transfer package.

## Целевая архитектура

1. **User Instructions** — глобальные правила пользователя, применимые во всех чатах и проектах.
2. **Project Instructions** — правила, специфичные для проекта Vico Forum и работы ChatGPT в нём.
3. **AGENTS.md** — общий рабочий регламент команды и репозитория для ChatGPT/Codex.

## Жёсткие правила для User Instructions

1. Всё, что уже находится в действующих User Instructions, считается исходным пользовательским baseline.
2. Новые правила могут попадать в User Instructions только если это **общее улучшение интеллектуальной работы или логики**, полезное во всех чатах и проектах.
3. Уже существующие в User Instructions правила про интеллектуальную работу и логику можно только **улучшать**, а не ослаблять или удалять.
4. Проектные, командные, GitHub/repository, role/permission/workflow-specific правила в User Instructions не добавляются.
5. Компактность достигается удалением лишней воды, повторов и вводящих в заблуждение пояснений, а не сокращением самостоятельных пунктов или склеиванием разных требований ради меньшего числа строк.

## Границы

- анализировать инструкции, их необходимость, формулировки, применение, дубли и распределение по слоям;
- не менять продуктовый код, архитектуру форума, CI, production или implementation PR;
- предыдущие drafts и research-результаты использовать только как исторический материал для сверки, но не как исходную конструкцию или обязательный target;
- не изменять действующие User/Project Instructions или `main:AGENTS.md` без отдельной прямой команды разработчика.

## Критерий готовности

1. Сначала определено требуемое поведение агентов и реальные классы ошибок, которые инструкции должны предотвращать.
2. Для каждого оставленного или добавленного правила доказана необходимость.
3. Для каждого правила выбран правильный слой.
4. User layer соблюдает отдельные жёсткие правила выше.
5. Итоговая система не теряет нужные самостоятельные требования, но не содержит лишней воды, дублей и вводящих в заблуждение уточнений.
6. Предыдущие ошибочные `52/52`, stress-PASS и transfer-readiness не используются как критерии качества новой архитектуры.

## Особый статус PR

Этот PR — рабочее пространство для анализа и фиксации материалов. Он не предназначен для merge в `main`.
